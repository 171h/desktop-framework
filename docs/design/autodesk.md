# AutoDesk 的设计共性

AutoDesk 系列软件（AutoCAD、Revit、Inventor、3ds Max 等）界面差异很大，但长期形成了一套稳定的桌面工作台范式。

## 共性拆解

### 1. 固定骨架

- 标题栏：应用标识、文档名、窗口控制。
- 应用菜单：文件、编辑、视图、帮助等全局动作。
- 快速访问工具栏：高频命令的固定入口。
- Ribbon：按任务组织的页签、功能组、按钮。
- 左右停靠面板：资源、图层、属性、工具选项。
- 中央视口：承载图形/模型/编辑对象。
- 底部区域：命令行、时间轴、输出、状态提示。
- 状态栏：坐标、单位、选择数量、捕捉/栅格开关。

### 2. 命令优先

AutoDesk 的按钮、菜单、快捷键和命令行最终都落到命令。界面只是命令的不同入口。这带来了：

- 一致的可发现性与可学习性；
- 宏、脚本、插件可以复用同一命令；
- 快捷键与工具栏不会各自维护状态。

### 3. Ribbon 的模块化

- 页签按任务组织（主页、插入、注释、视图、管理、附加模块）。
- 功能组内部按命令频率与尺寸分级。
- 窄窗口自动降级为紧凑按钮或溢出菜单。
- 上下文页签随选择/模式出现。

### 4. 可定制工作区

- 面板可停靠、浮动、隐藏、调整宽度。
- 不同任务保存为工作区（建模、审阅、出图）。
- 用户布局在下次启动恢复。
- 企业可以下发标准工作区。

### 5. 视口与交互

- 平移/缩放/旋转有统一手势。
- 选择、悬停、捕捉反馈明确。
- 大场景使用按需渲染、层级细节、空间索引。
- 常用命令有固定快捷键和状态栏提示。

## 本框架的映射

| AutoDesk 概念 | Desktop Framework |
| --- | --- |
| 应用菜单 | `@desktop-framework/menu` 的 `AppMenu` |
| 快速访问工具栏 | 命令 `toolbar` 元数据 + `QuickAccess` |
| Ribbon | 命令 `ribbon` 元数据 + `vscode-ribbon` |
| 工作区 | `workbench` Pinia store + `WorkspacePreset` |
| 停靠面板 | `workbench.registerView()` + `DfSplitLayout` |
| 视口 | `surface` WebGL2 画布 + 可扩展节点服务 |
| 命令行 | `CommandPalette` + 命令注册表 |
| 状态栏 | `statusbar` 服务 + nusys-ui 元素 |
| 插件/附加模块 | Cordis 插件 |
| 企业标准界面 | 默认预设 + 配置 + 远程运行时 |

## 刻意不做的事

- 不复制 AutoDesk 的视觉资产与品牌。
- 不强制所有产品使用同一种视口；`surface` 是可替换的主视图插件。
- 不把 Ribbon 写死成静态配置；命令元数据才是事实来源。
- 不允许业务插件直接改框架内部状态；通过服务与事件协作。

## 一致的体验从哪里来

不是“所有软件长得一样”，而是：

1. 相同的布局语义与快捷键习惯；
2. 相同的命令执行与错误反馈；
3. 相同的面板拖拽、保存、恢复逻辑；
4. 相同的主题令牌与组件行为；
5. 相同的性能预算与启动骨架。

这五点由框架统一提供，产品只需要贡献自己的命令、视图与数据。
